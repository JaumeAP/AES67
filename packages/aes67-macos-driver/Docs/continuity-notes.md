Git workflow: autonomous local merge (no pull request) per git-rules. Response style: Catalan replies, English code/commits. Start replies with `Rebut: <order>`. Numbered lists only, no bold/headers/tables.

Architecture invariants: RT-safe thread boundaries (IO thread touches only `RTSafeStreamInterface` and the lock-free ring buffers, never `StreamManager`), AudioServerPlugIn via libASPL. Stream configs persist as JSON, and the role a stream runs in is a field in that file (`PersistedStreamConfig::isTransmit`), not something read back out of the announced direction -- a sender announces `a=recvonly`, because that is what a reader of the description can do with it.

Platform-free core: `packages/aes67-core`, a sibling package in this monorepo, consumed with `add_subdirectory` — SDP, RTP wire header, jitter buffer, packet pool, PLL, resampling, channel mapping, configuration, the ring buffer, the RT-safe view over it, the PTP time types and clock-source interface, and the PTP peer, RTCP receiver and Dolby model tables. What stays here is macOS plus `aes67_net`, the socket layer, which supplies the four `NetworkUtils` symbols the core declares without implementing. The boundary was reviewed on 2026-09-03 and deliberately left where it is. Its test suites run from the root `ctest` since 2026-09-05. Clone with `--recurse-submodules`: doctest, at the root `external/doctest`, is the one submodule left.

Build/test: macOS (Apple Silicon + x86_64), CMake out-of-source. Suites are doctest, labelled `unit`/`timing`/`network`/`integration`/`interop`, each with `TIMEOUT 60` (`PTPLoopback` 90, `PTPMaster` 90 since it carries a five-second cadence case). `IntegrationAudioPath` needs real multicast and fails outside the gate by design.

**This repository cannot be configured off a Mac**: `project()` declares OBJCXX, so `cmake` fails on Linux before anything builds. A remote session can still check a change by compiling and linking the affected targets by hand (`g++ -std=c++20 -I. -I../aes67-core`), with a local shim for `net/if_dl.h` and `CommonCrypto/CommonDigest.h` and a stub for the CoreAudio-bound symbols — neither committed.

Gates, local and remote. `scripts/gate.sh` is the local one, run by `.githooks/pre-push` (opt in per clone with `git config core.hooksPath .githooks`): build, `ctest -LE timing` and the core's platform contract by default; clang-tidy with `--analyse` or `AES67_ANALYSE=1`; `--sanitize` and `--tsan` run everything but `network`; `scripts/coverage.sh` reports llvm-cov. GitHub Actions carries what a Mac cannot: `daemon-interop.yml` runs this driver against a real `aes67-linux-daemon` on a Linux runner, with `linux-ptpd.yml`, `ravenna.yml`, `ravenna-lkm.yml`, `macos.yml` and `t41-ptp.yml` beside it. The older note that Actions was disabled and deleted has not been true since those jobs were written.

Static analysis: `.clang-tidy` runs the defect families and leaves style off; `WarningsAsErrors` is deliberately narrower than `Checks`. Install with `python3 -m venv ~/.local/venvs/cpptools && ~/.local/venvs/cpptools/bin/pip install clang-tidy==21.1.6`.

App icons: `scripts/make-app-icons.swift` draws all four (Manager, Controller, installer, uninstaller) with CoreGraphics at every size an `.icns` holds, and `scripts/make-app-icons.sh` packs them with `iconutil` into the package that ships each bundle. The drawing is the source; the `.icns` files are committed so a build needs no drawing step. Re-run the script after editing it. The small sizes are drawn rather than downsampled.

Manager app previews: `#Preview` blocks live in `packages/aes67-macos-manager/Views/Previews/`, kept out of `build.sh`'s source list because the macro needs full Xcode.

Related repositories: `aes67-core` and `t41-ptp` are packages of this monorepo, not separate repositories — their GitHub originals are archived, and so is `JaumeAP/QNEthernet`, which arrives inside t41-ptp as `libraries/QNEthernet`. `JaumeAP/AES67-master-box-` (the grandmaster firmware) is standalone, `main` at 2f66e20, carrying t41-ptp as the `lib/t41-ptp` submodule at `bc9cd69`. The box does NOT consume `aes67-core`, and after weighing it on 2026-09-03 it stays that way.

Profiles: `packages/aes67-profiles` holds the compatibility profiles, the Dolby model catalog and the PTP profiles as dependency-free tables read by this core and by the Teensy firmware. A profile is a filter, never a capability grant. The flow limit is bytes, not channels: `aes67-core/NetworkEngine/RTP/PacketBudget.h` (1500-byte frame, 1472 RTP bytes) decides what fits at a packet time, `StreamManager::canAddStream()` refuses what does not in both directions, and the transmit splitter takes min(profile cap, `StreamChannelMapper::kMaxChannelsPerFlow` = 64, budget at the device rate and 1 ms). RAVENNA's profile permits 64 channels a flow; AES67, Dante, Dolby and ST 2110-30 keep 8.

A packet's length is a fraction, not a whole number of microseconds: `PacketBudget::packetInterval()` returns whole nanoseconds plus a remainder over the sample rate, and both `RTPTransmitter` and `Tools/AES67TestSender` carry that remainder. At 48 and 96 kHz the division is exact and nothing shows; at 44.1 kHz rounding it ran 0.07% fast, which drains the ring buffer the device fills for as long as the stream lasts.

Test and interop tooling in `packages/aes67-macos-driver/Tools/`, all built by the gate. Run the two simulations after touching SDP generation, SAP or the profiles:

1. `AES67InteropSim` — offline interop against the RAVENNA Linux daemon, reporting on `Tests/support/DaemonSap.{h,cpp}` (that daemon's own send and receive path, mirrored from its source) rather than restating its rules.
2. `DanteInteropSim` — the same shape against Dante Controller 4.18.1.1, both directions, every profile, with what only a live Controller can settle printed as `[??]` and never failed.
3. `AES67LiveDaemonInterop` — the live counterpart, against a real daemon built with `-DFAKE_DRIVER=ON` in `daemon-interop.yml`. Three directions: the daemon's own source heard by our `SAPListener` and described by our `RTSPClient`; our announcement found by its SAP browser; and our announced SDP accepted as a sink of its own, with audio sent to the group that SDP names. Whether those packets come off the wire cannot be read there — the daemon's receive path is the kernel module, which the fake driver manager stands in for — so the sink flags are printed rather than asserted, and GStreamer's `rtpL24depay` answers that question in the same job instead.
4. `AES67TestSender` — sine-wave RTP multicast, SAP announcements through the driver's own `SAPAnnouncer` (payload type included), a deletion on the way out, and a random starting sequence number.
5. `AES67TestReceiver` — RTP statistics per SSRC, RFC 3550 §A.1/A.3, and the channel count derived from the payload size and the timestamp step when the stream is steady enough to read one.
6. `AES67SAPMonitor` — hears announcements through `SAPListener::parseAnnouncement`, and says what a deletion withdraws by the identity it carries.
7. `ravenna-announce`, in `packages/aes67-ravenna/Tools/` — advertises one session over mDNS and answers RTSP for it; sends no audio.
8. `AES67PTPStressRun` — this driver's own `PTPMaster` and `PTPSlave` against each other over a live interface, sampling lock, offset and path delay every second; `--csv` keeps the samples out of the engines' log.

What moved to the Eines repository on 2026-09-16, because none of it reads a byte of this driver: the impairment relay is `aoip-stress impair` (`packages/aoip-stress-lab`), and `HALValidate` and `QuickCapture` are in `packages/macos-audio-development/tools`. `scripts/validate-hal.sh` still drives the first, finding it in the usual checkout or through `HAL_VALIDATE`.

The outside opinion, and how to ask for it again. Eines' `aoip-stress` (`load`, `monitor`, `ptp`, `session`, `impair`) is written apart from this driver, and `ffmpeg` decodes a stream from a hand-written SDP (`-protocol_whitelist file,udp,rtp -i x.sdp -af volumedetect`) with no code of ours in the path. Worth repeating after anything that touches RTP or PTP: our sender read by `aoip-stress monitor`, its generator read by our receiver, our `PTPMaster` read by `aoip-stress ptp`, and any stream decoded by ffmpeg. Three defects came out of exactly that and nothing here could have found them — the master announced 125 ms and sent at 131.9; the packet interval was truncated to whole microseconds; a unicast session never opened its socket, because the receiver joined a multicast group whatever address it was given. `packages/audio-network/references/aes67-third-party-verifiers.md` in Eines lists the third-party verifiers, emulators and analysers worth knowing about, with what each settles and whether it runs on this Mac.

## Session summary — the tools audited, and what outside code found (2026-09-15/16)

All eleven test tools were walked through one at a time; eight had a defect, from a SAP header the AES67 daemon could not hear to a tool with no build target at all, and three moved to Eines. The offline simulations were then wired to `NetworkEngine/TxSession.h`, the one place a transmit session's fields are decided, because each had built its own copy by hand and so could not see a change to what the driver announces. Verification against code written elsewhere found four driver defects — the PTP send cadence, the packet-interval truncation, unicast reception, and an ignored `AES67_CONFIG_PATH` — each now fixed and pinned by a test. `daemon-interop.yml` grew a third direction and a GStreamer receiver, the four app bundles got icons drawn by a script, and coverage went from 64.89% to 67.05% of lines, with `AES67IOHandler` from 8.7% to 85.9%.

4. Where a `StreamConfigManager` that finds no configuration should write. It defaults to `/Library/Application Support/AES67Driver/streams.json`, which an unprivileged process cannot create, so the first save on a fresh machine fails and says so only in the debug log. `AES67_CONFIG_PATH` wins when set. Whether the default should fall to `~/Library/Application Support` is a question about what a driver inside `coreaudiod` should own, and it changes where an installed driver keeps its streams.
5. The `t41-ptp` servo split has not been through the Teensy toolchain. `pio run` on the box before flashing anything.
6. `TestPTPMasterBoxInterop` replays bytes built from the library's source. A real capture off the box would be worth more and drops into the same shape.
7. `NetworkErrorHandler::attemptRecovery` in the core clears its own latch before returning, so `isInRecovery()` is false wherever a caller can observe it and a second recovery always starts. Pinned by a test that documents the behaviour; making the latch real is a behaviour change.
8. The firmware PR `JaumeAP/DTS-Player#33` needs `pio test -e native` before merging, and a decision on `-DDTS_DSP_QMF_FLOAT`.
9. `dts-dsp` needs `COPYING.LESSER`, the LGPL-2.1 text, which nobody has downloaded yet.
10. `PTPMasterSettings` keeps the two message intervals in milliseconds, and milliseconds cannot express every legal rate: 16 Sync per second is 62.5 ms and the field is an `int`. Both rates come from one exponent settled in the constructor, and a non-power-of-two setting is rounded to the nearest legal interval and sent at that rate rather than misdeclared. What is left is where the rounding happens: `int8_t logSyncInterval`/`logAnnounceInterval` in the settings, with milliseconds as a rendering for `ManagerApp`, would put it where the value is chosen. That is a settings file format change, and the struct lives in `aes67-core`. `JaumeAP/AES67-master-box-` is already built that way (`src/profiles.h`).
